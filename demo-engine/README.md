# 결정론 수박게임 시연 엔진 — 재현 프롬프트

AI 코딩 에이전트(Claude Code 등)에 **그대로 붙여넣으면** 아래 결과물이 나오는 프롬프트 모음입니다.

- **브라우저 캔버스 + 코드만으로 만든 수박게임 시연 클립** (영상 편집 프로그램 0)
- **완전 결정론** — 같은 프레임 번호는 언제 그려도 같은 픽셀. 2회 렌더 SHA 일치
- **진짜 강체 물리** (연출로 겹치는 척이 아니라 접촉 해석 결과)
- **게임오버 라인 규약 내장** — "낙하 이후의 과일은 라인 위로 올라가지 않는다"를 **시뮬 불변식**으로 강제하고, 노출 프레임 전수를 게이트로 검사
- 과일 실루엣 = SVG에서 추출한 큐빅 베지어 (AI가 그린 그림이 아님)
- 세로 1080×1920 / 30fps / 심리스 루프 / mp4 출력

여기 있는 건 **게임 시연부만**입니다 — 나레이션·씬 연출·자막·업로드 절차는 들어있지 않습니다.

STEP 1의 과일 데이터는 이 저장소의 [`extra/fruit_vec.json`](../extra/fruit_vec.json) · [`extra/svg2fruit.py`](../extra/svg2fruit.py) · [`svg/`](../svg/)와 같은 것입니다. 그대로 가져다 쓰면 STEP 1을 직접 할 필요가 없습니다.

## 왜 물리를 미리 굽는가

테트리스는 격자 위 이산 사건이라 시뮬을 렌더 안에서 돌려도 재현됩니다. **강체 접촉은 다릅니다.** 반복 해석기가 스텝 순서·누적 상태에 민감해서, 시크할 때마다 미세하게 다른 결과가 나옵니다.

그래서 물리는 **오프라인에서 한 번만** 돕니다.

```
suika_bake.cjs   고정 dt(1/120) · 고정 시드 · 서브스텝 4 → 프레임별 스냅샷
        ↓
suika_snaps.json { meta, tiers, frames:[[{i,k,x,y,a}...]], merges, drops, clears }
        ↓
렌더러          frames[f] 조회만. 순수 f(t). 물리 없음
```

단일 머신 1회 베이크 = 픽셀 락의 소스입니다. 재현자가 다른 머신에서 다시 구우면 부동소수 차이로 스냅샷이 달라질 수 있습니다 — **결정론은 "누가 굽든 같다"가 아니라 "같은 스냅샷이면 언제 그려도 같다"** 입니다. 클립을 재현하려면 스냅샷 JSON도 같이 보관하세요.

## 라인 규약 (STEP 3)

수박게임에서 눈에 가장 먼저 걸리는 결함은 **과일이 데드라인 위로 솟는 것**입니다. 그리고 그 결함은 대개 물리가 아니라 **판정 반경을 잘못 잡아서** 생깁니다.

- 판정에 물리 반경을 쓰면, 화면에는 잎·꼭지까지 포함한 더 큰 실루엣이 그려져서 **눈에는 넘친 것으로 보입니다.** 판정 반경 = 렌더 실측 반경(`VIS_R`).
- 착지 판정을 "모든 접촉"으로 잡으면 공중에서 스친 과일까지 착지 처리되고, 라인 보정이 즉시 발동해 **순간이동**이 생깁니다. 착지 = 정적 바디 또는 이미 착지한 과일과의 접촉(전이적 전파).
- 보정은 서브스텝당 상한을 둡니다(`0.03m`). 하드 클램프는 그 자체가 순간이동입니다.

그리고 **눈으로 보는 대신 노출 프레임 전수를 스크립트로 검사**합니다(STEP 7).

## 정직성에 관하여

STEP 4의 클라이맥스는 **authored 셋피스**입니다. 최고 티어까지 자연 도달하려면 최소 과일이 1,024개 필요해서 20~30초 클립에서는 수학적으로 불가능합니다. 그래서 중앙에 키스톤을 두고 같은 티어를 위에서 떨어뜨려 한 칸씩 올립니다.

이건 놀이용 연출로서 괜찮습니다. **다만 "AI가 플레이한 기록"이나 "자연 발생한 결과"라고 말하지 마세요.** 화면에 뜨는 숫자·배지는 손으로 적지 말고 전부 시뮬이 기록한 사건(`merges`·`clears`·`drops`)에서 파생시키세요 — 그게 이 계열 프로젝트의 유일한 안전장치입니다.
